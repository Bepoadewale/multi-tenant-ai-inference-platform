# GPU Lab Risk Register

Initial risks from repository inspection and the project constraints. Update likelihood, impact, mitigation, owner, and evidence as research and implementation proceed.

| Risk | Impact | Initial mitigation / gate | Status |
| --- | --- | --- | --- |
| G6 capacity or L4 quota unavailable | GPU work cannot start or pushes project elsewhere | Applied On-Demand G/VT quota is zero in `us-east-1`, `us-east-2`, and `us-west-2`. AWS email reports the 4-vCPU `us-east-1` request denied while Service Quotas history still says `CASE_OPENED`. The owner reports manually sending an appeal through the existing case; no approval is confirmed. Do not duplicate the request. Recheck status before launch. | Blocked pending AWS quota decision/status reconciliation |
| Existing dependency audit fails | PR CI may fail and known vulnerable dependencies remain in local environment | Shared minimum-version constraints were added in draft PR #31; local install, Docker build, clean-room validation, and `pip-audit` pass on that branch. Await CI/review/merge; constraints are not a full lock file. | Remediation in PR #31; review pending |
| Total AWS resources exceed the $25 ceiling | Unauthorized spend | Price all resources, cap runtime, use one instance, no NAT/managed services, gate exact plan, terminate after batch | Open; no spend |
| Session interruption leaves instance running | Continued spend with a potentially large overrun | Use an exact-deadline EventBridge Scheduler termination of the one instance with scoped role, guest-side systemd shutdown timer, EC2 shutdown-to-terminate behavior, and delete-on-termination storage; test each control independently and verify deletion after every batch. | Proposed; not implemented or tested |
| Existing/shared AWS resources mistaken for project-owned | Damage or cross-project impact | Read-only exact project-tag and EC2 instance queries in `us-east-1` returned no matches; this does not exclude untagged/differently tagged resources. Use dedicated names/tags/state/root and destroy only exact project root. | Initial scoped inventory checked; untagged resources remain unknown |
| Standard Ubuntu driver/kernel/CUDA incompatibility | GPU unavailable or unstable | Pin a documented compatible stack; manual validation before Ansible; preserve recovery path | Open |
| L4 VRAM insufficient for model/runtime/context/concurrency | Startup failure or OOM | Begin with 1.5B model, measure; cap context and concurrency; don't co-load large models | Open |
| Mutable image/model artifact produces irreproducible results | Unknown code/model behavior | Pin Canonical Ubuntu AMI ID and verify owner/name/architecture/state in preflight; pin vLLM image digest, model revision, download source, and SHA-256. The AMI is not yet tested on an L4. | AMI pin in PR #40; runtime validation open |
| Gateway reports inaccurate token usage or leaks reservations | Tenant overrun, quota bypass, incorrect cost | Audit tokenizer/count/reconciliation, client cancellation, error and Redis failure paths; tests before live use | Open |
| Redis failure permits unbounded inference | Capacity overload and tenant impact | Preserve fail-closed admission; test dependency failure and reservation cleanup | Open |
| Prompt/completion or credentials leak through logs/evidence | Tenant privacy or account compromise | Metadata-only telemetry, redact outputs and headers, scan evidence before commit | Open |
| Single host is mistaken for HA or GPU isolation | Misleading engineering claims | Explicitly label single point of failure and logical-only tenancy everywhere | Open |
| Benchmark timing is asynchronous or under-repeated | False performance conclusions | Warm-up, device synchronization/events, repeated trials, record raw outputs and limitations | Open |
| Local validation regression while adding GPU path | Loss of proven CPU baseline | Run existing suite before/after; preserve CPU ONNX fallback and clean-room gate | Open |
| External model license or terms unsuitable | Reuse/redistribution issue | Verify current official model card/license before fetching; do not redistribute weights | Open |
| LLM release plan trusts supplied champion or model-file digest | Approval could bind a false starting state or false provenance | The authenticated planning API checks candidate metadata against the sanitized MLflow run and persists exact manifests, but the caller supplies the champion manifest and preverified model digest. Before deployment, the host controller must compare the champion against independently recorded active state and recompute artifact digests from downloaded files. Plan approval alone must not authorize deployment. | Open; controller and live verification outstanding |
| Evidence files expose sensitive values or bloat public Git | Security and repository maintainability | Sanitized manifest, no state/plans/credentials; keep bulky raw artifacts outside public repo | Open |
