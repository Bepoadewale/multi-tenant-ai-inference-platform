# Ticket 42 — Refresh the pinned-AMI Terraform preview

## Objective

Re-run the isolated EC2 Terraform preview after pinning the Ubuntu AMI. Review the
planned resources and security settings without applying anything, and preserve a
sanitized record that can be compared with a future remote-state plan.

## Current state

The preview completed on 2026-11-27 in `us-east-1` using the verified AWS account
profile, `g6.xlarge` in `us-east-1c`, Canonical Ubuntu 24.04 amd64 AMI
`ami-0a951420c495183dc`, 100-GiB root storage, and a six-hour expiry timestamp. It
proposes 14 creates, zero changes, and zero destroys. The saved plan is ignored under
`.local/` and is not suitable for apply because it uses a temporary copy with the S3
backend removed. The AWS quota remains zero, and no cloud resource was created.

## Resource and security review

The 14 planned resources are:

1. One `g6.xlarge` EC2 instance.
2. One VPC, subnet, internet gateway, route table, and route-table association.
3. One security group.
4. One EC2 instance role, its SSM policy attachment, and one instance profile.
5. One expiry role and policy.
6. One EventBridge Scheduler schedule group and one one-time expiry schedule.

The plan shows IMDSv2 required and a 100-GiB encrypted gp3 root volume configured to
delete on instance termination. The instance receives a public IP so it can reach
package and model sources without a Network Address Translation (NAT) Gateway; the
security group has no inbound rules and limits outbound traffic to TCP ports 80 and
443. Public IPv4 has a running-time charge, included in the project's cost estimate.

## Research and decisions

- The exact pinned AMI was rechecked using AWS `DescribeImages` in a separate read-only
  query and its owner, image family, architecture, and availability were verified in
  the preceding package.
- This plan refresh was generated by `scripts/gpu-ec2-preview-plan.sh`, which copies
  the root, removes its backend block from the copy only, initializes a local state,
  and runs `terraform plan`. It does not run the project preflight and therefore does
  not check the applied quota. Terraform's instance-type offering data confirms an
  AZ offering, not EC2 capacity or quota.
- The local plan has SHA-256
  `d33721981fdeaec4b513d3a738553c155423d50aa8bb7851c31ef0c5da70bd44`. The raw plan
  remains outside Git and must not be applied.
- AWS `get-service-quota` and request-history reads confirm the applied quota is
  `0.0`, while history says `CASE_OPENED`. AWS denial email and API status remain in
  conflict. No quota or support mutation was made during this plan run.

## Commands and validation

- `scripts/gpu-ec2-preview-plan.sh` — succeeded; verified the expected AWS account,
  read the offered instance type, and saved a local-state preview under ignored
  `.local/`.
- `terraform show -json` was run from the preview copy's directory because Terraform
  needs that copy's installed provider schema. A first attempt from the repository
  root failed to load the provider schema; rerunning from the initialized preview
  directory succeeded. The filtered review printed only resource addresses/actions
  and selected security settings, not the whole plan.
- The resulting plan reports 14 to add, zero to change, zero to destroy, complete and
  syntactically applyable. “Applyable” is Terraform's plan-format field only; it does
  not grant approval or make this local-backend preview safe to apply.
- `git check-ignore` confirmed the raw saved plan is ignored by Git.

## Financial and security considerations

This was a read-only AWS plan: no infrastructure was created and no cost was incurred.
The six-hour expiry value was only a tag/schedule input in a plan. It did not start a
timer or create a Scheduler resource. The local-state preview has no shared remote
locking and does not establish the final resource cost. The project's USD $25 ceiling,
zero-quota gate, exact remote state, expiry test, and explicit plan review still apply.
