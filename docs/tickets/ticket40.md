# Ticket 40 — Pin and verify the Ubuntu AMI

## Objective

Make the isolated GPU Terraform root use one reviewed Ubuntu image identifier.
Prevent image discovery from silently selecting a different machine image on later
plans, and make the guarded preflight reject images outside the approved Canonical
Ubuntu 24.04 amd64 server family.

## Research and design

- AWS `DescribeImages` in `us-east-1` returned the chosen AMI as available, x86_64,
  with Canonical owner ID `099720109477` and Ubuntu Noble 24.04 gp3 server name.
- The AMI ID is an input to Terraform and is shown in the example tfvars file with a
  note to recheck it before use. The dynamic `most_recent` lookup was removed so a
  later plan cannot silently change the host image.
- Read-only preflight verifies the supplied AMI's publisher, name pattern, CPU
  architecture, and current availability before plan/apply.
- Terraform destroy planning still receives the exact AMI variable but does not
  resolve a new AMI from the catalog. This avoids making teardown depend on a mutable
  image query.
- Official references: [Ubuntu AMI discovery and owner verification](https://ubuntu.com/aws/docs/aws-how-to/instances/find-ubuntu-images/)
  and [AWS AMI discovery](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/finding-an-ami.html).

## Issues and troubleshooting

- The first Terraform validation after removing the AMI data source found an output
  still referenced the deleted data block. Updated the output to use the pinned input;
  validation then passed.
- The first shell syntax check found an apostrophe in a shell parameter error string
  that broke quoting. Reworded the message and reran shell syntax checks successfully.
- The initial targeted test expected the preflight to make two AWS calls. Adding the
  AMI description check changed that call sequence, so assertions were updated to
  verify the image lookup and fail-closed behavior.
- An initial `make verify` in this temporary worktree could not find a virtual
  environment and then lacked ignored ONNX test fixtures. A symlink to the existing
  project virtual environment and test fixtures generated by the repository's model
  creation script allowed the full suite to run. These remain local and are not
  intended for the PR.

## Security and financial considerations

All cloud operations in this package were read-only metadata queries. No credentials
or secrets are stored. No AWS resource, GPU instance hour, or spend was created. The
AMI selection does not bypass the denied quota, the $25 project ceiling, exact-plan
review, expiry, or teardown gates.

## Evidence and limitations

Local automated tests and Terraform validation establish that the wrappers pass the
AMI input and reject incorrect metadata in mocked preflight cases. They do not prove
that this image boots on G6, that its kernel works with the researched NVIDIA driver,
or that SSM and GPU configuration succeed on a real instance. Those checks remain
blocked on quota and later authorization.
